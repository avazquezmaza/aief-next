# Release v4.0.0

AIEF 4.0 is the Change contract, not a workflow engine (ADR-038). It keeps what real projects use
and removes what only a `manifest.json` could switch on. No project — the 11 measured in Analysis
0154, or this repository — had a `manifest.json`.

## Upgrade notes

Breaking changes:

- **`manifest.json` is no longer read.** `aief verify` names a leftover one as "no longer read
  (AIEF 4.0, ADR-038)"; it has no other effect. A manifest's `status` no longer overrides
  `change.md`.
- **Tracks and the workflow engine are removed** (`lite`/`standard`/`governed`, stages, gates).
  `(gate:<id>)` lines are now ordinary tasks. Use `(human)` or `(review)` for approvals.
- **Dependencies move to `change.md`.** Replace a manifest's `dependsOn` with:

  ```markdown
  ## Depends on

  - 0002-base-api
  ```

  `aief new-change <name> --depends-on <id>[,<id>...]` writes it. `status --graph` and
  `status --next` read it. `aief close` now warns, without blocking, while a dependency is open.
- **Removed:** Loop (`loop.md`), the Harness log (`hooks.md`), SDD providers and
  `knowledge/sdd-provider.json`, requirement verification (`aief verify --requirements` is now an
  unknown option), and `ai-specs/` discovery in `doctor` and `prompt`.
- **`aief propose` never delegates to OpenSpec.** It always creates a local Change with
  `proposal.md`, and AIEF never runs an external tool.
- **`aief bootstrap` and `aief doctor` no longer check for OpenSpec or SpecBoot.**
- **`aief verify --json`** no longer has the `manifestStatusDrift` field.
- **The `requirements-analysis-instructions` Skill and the `prompt-skill-suggestion` Hook are
  removed.** Both only worked with an SDD provider.

Also in 4.0 (Change 0155):

- **`(human)`/`(review)` Acceptance Criteria in `spec.md` are enforced** like those in `tasks.md`.
  `close` refuses while one is unchecked or `[-]`; `verify --strict` fails an open Change and adds a
  notice for a closed one. Unlabeled criteria stay informational.
- **Detection skips nested repositories**, so a cloned repository inside a project no longer drives
  its detected stack or Skills.

## Summary

Four Changes since 3.5.0 (0154–0157):

- **Analysis:** real use measured across 11 local projects (93 Changes) and this repository; the
  core loop is used, the manifest-based features are not (0154).
- **Fixes:** nested repositories in detection, `spec.md` approvals enforced (0155).
- **Definition:** what 4.0 removes, rescues and merges, approved by the owner; ADR-038 (0156).
- **Implementation:** the removals, `## Depends on`, the close notice, docs, diagrams, version
  4.0.0 and these notes (0157).

`cli/src`: 8,946 → 5,431 lines (70 → 47 files). Tests: 1,152 → 699, removed with the features they
covered. `AGENTS.md` no longer explains tracks or gates. One ADR added (ADR-038). No runtime
dependency added; `@aief/cli` remains dependency-free.
