# Release v3.4.0

## Upgrade notes

- **Node.js >= 22 is required** (0126/0142). Node 18 and 20 are end-of-life and no longer tested;
  `engines.node` is `>=22`.
- **`aief new-change`, `analyze`, `propose` and `enrich` switch to a new branch** `<type>/<id>-<slug>`
  when run on `main` or `dev` (0114/0117). On any other branch they stay put. `--no-branch` opts out.
  AIEF never commits, pushes or deletes branches.
- **`aief close` enforces Workflow Gates for Changes that declare a `track`** (0124/0125, ADR-037).
  Each `review`/`approval`/`security_review` gate the track declares needs a human-checked
  `- [x] (gate:<id>) …` line in `tasks.md`. Changes without a track are unaffected.
- **`aief bootstrap` no longer writes `.github/workflows/aief-verify.yml`** into adopted projects
  (0139). Its `npx --yes aief verify` step pointed at an unpublished package name. Wire
  `aief verify` into your CI as shown in the docs.

## Summary

Forty-two Changes since 3.3.0 (0105–0147; two Changes share `0122`):

- **Governance enforcement:** Workflow Gate authority defined and enforced by `aief close` for
  tracked Changes (0124–0125, ADR-037); one branch per Change enforced by the CLI (0114, 0117);
  guidance against scope creep beyond a Change's acceptance criteria (0127); operational guardrails
  (no secrets in tracked files, no AI `Co-Authored-By`, confirm outward-facing actions, prefer PRs)
  as explicit policy (0111).
- **Security:** path traversal in the Jira Requirement Source provider fixed (0105); malformed Jira
  exports handled cleanly (0116); `docs/security-model.md` with trust boundaries, threats and
  mitigations (0132); supply-chain hardening in CI with CodeQL, dependency review and SBOM (0133);
  secret scanning enabled and a transitive `qs` vulnerability fixed in study fixtures (0136);
  bootstrap's generated GitHub workflow removed (0139).
- **Verification and integrity:** `aief verify --json` (0138); numeric Change-ID collision detection
  in `verify` and `status` (0135, 0137); `verify --strict` bullet and historical-marker gaps (0109,
  0115, 0120); `close` keeps `manifest.json` status in sync (0131); evidence-report provenance
  (0129); executable architecture fitness functions for layer boundaries (0128); accurate Graph
  cycle reporting (0123).
- **Assistants and detection:** Kiro as a fifth native assistant (0112, 0113); assistant parity
  validated with Codex, Claude Code and Gemini CLI (0121); Java, Maven, Quarkus, Camel, OpenShift,
  Kustomize and Argo CD detection (0140); `aiRoadmap` false positive from AIEF's own `AGENTS.md`
  fixed (0141); starter standards derived from the Skill catalog (0106, 0108); YAML-frontmatter
  Skill packages in `ai-specs/skills/` (0110).
- **Platform, CI and docs:** CI lint step (0119); CI apt mirror flakiness (0122); canonical
  `AGENTS.md` for `bootstrap <name>` (0118); external Codex audit and its documentation-integrity
  findings (0130, 0134); minor consistency fixes (0107); README drift and Node requirement (0142).
- **Laya experiment (no engine change):** analysis (0143), an opt-in example in
  `examples/laya-triage/` (0144), and an evaluation on 131 real Changes that found no reliable
  zero-shot signal. Fine-tuning stopped at a no-go checkpoint, and the example is marked
  experimental and unvalidated (0145).
- **Release:** readiness and documentation audit (0146); version 3.4.0 and these notes (0147).

One ADR added (ADR-037). No runtime dependency added; `@aief/cli` remains dependency-free.
