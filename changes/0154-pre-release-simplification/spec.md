# Specification

## Goal

The owner can decide, from real-use evidence, what to remove, rescue, merge and add before AIEF's
first wider release.

## Requirements

### R1: Usage

- What the 11 local projects actually use: Changes, evidence, approvals, standards, skills,
  manifest features, and how they version AIEF files.
- What the AIEF repository itself uses of its own features.

### R2: Cause of non-use

- For each unused component: whether it is undiscoverable, unneeded, or not working, with a
  reproduction in a disposable project.

### R3: Bugs

- Each bug with reproduction, file reference and severity. Claims that turned out not to be bugs
  are recorded as such.

### R4: Verdicts and plan

- A verdict per component (keep / rescue / merge / remove).
- Additions justified by observed use, including the ECC ideas that fit.
- Three waves of follow-up Changes in order.

### R5: Findings

- A `## Findings Status` table with IDs, severities and statuses.

## Acceptance Criteria

- [x] R1: Usage documented with numbers and project references.
- [x] R2: Cause of non-use documented per component.
- [x] R3: Bugs documented with reproductions.
- [x] R4: Verdicts and wave plan recorded.
- [x] R5: Findings Status table present.
- [x] (human) Approve or edit the verdicts and the wave plan.
