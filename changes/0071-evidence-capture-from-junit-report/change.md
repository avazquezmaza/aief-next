# Change

## ID

`0071-evidence-capture-from-junit-report`

## Type

General

## Objective

Filling in `evidence.md`'s `## Verification` section today means manually reading test-runner
output and typing counts by hand. Add `aief close --evidence-from <path>`: it reads an
**already-written** test report file (produced by the user's own test runner/CI — AIEF never
executes anything) and fills in that one, objectively-derivable section for you, then proceeds
with `close`'s normal readiness checks. Every other section (Summary, Findings, Risks,
Recommendations, Lessons Learned) is left for a human or assistant to write — this Change captures
numbers, not judgment.

## Governance note (per ADR-021 / the earlier evaluation of this idea)

ADR-021 explicitly rejects `command_result`/`external_reference` evidence types (they require
execution/network) for Requirement Verification, and forbids `executeCommands`/`network` in
`FORBIDDEN_CAPABILITIES` across Skills, Hooks, and Verification Rules. This Change stays inside
what's actually allowed: it **only reads a file the user already produced** — the same
`file_assertion`-shaped operation `evidence-reference-integrity` (Change 0049) already performs —
and never runs a test, a command, or reaches the network. It is not a Verification Rule and does
not touch the Requirement Verification engine at all; it is a `close`-time convenience that writes
to `evidence.md`, the same way `aief bootstrap` already auto-writes the Adoption Change's
`evidence.md` ("Generated by AIEF during adoption").

## Scope

### In scope

- `aief close --evidence-from <path> [--yes] [--change <id>]`: reads `<path>` (resolved relative to
  cwd, same trust model `enrich --file <path>` already uses — a path the person running the CLI
  typed themselves).
- Parses **JUnit XML** — the one format supported this Change, chosen for being the most portable
  test-report shape across ecosystems (Jest, pytest, PHPUnit, go test, Mocha, RSpec, `node --test`
  via a JUnit reporter, all commonly emit it). Extraction is a fixed, deterministic regex over
  `<testsuite ...>` root attributes (`tests`/`failures`/`errors`/`skipped`/`time`/`name`), summed
  across every `<testsuite>` found — the same "fixed regular expressions, never a heuristic parser,
  never AI" discipline `sdd-model.js` already established for Markdown extraction. No XML parser
  dependency is added (still zero runtime dependencies).
- Fills in `evidence.md`'s `## Verification` section: replaces it wholesale only if it is still the
  literal `"Pending."` placeholder or was itself a previous capture from this same feature (safe,
  idempotent re-capture after fixing a failing test) — otherwise, never overwrites human-written
  prose; appends a clearly-marked subsection below it instead.
- An unreadable path or a file with no `<testsuite>` element found is a clear, exit-1 error — never
  a silent no-op, never a guess.
- `close`'s existing readiness checks and `--yes` behavior are otherwise completely unchanged —
  `--evidence-from` without `--yes` is a "capture only" run, identical in spirit to `close` without
  `--yes` today.

### Out of scope

- Executing tests, `npm test`, or any command — AIEF never runs anything (ADR-021's own
  discipline).
- Any other report format (TAP, Cobertura coverage XML, etc.) — a follow-up Change if the project
  wants one; JUnit XML alone covers the most common case.
- Any change to the Requirement Verification engine, evidence types, or Verification Rules —
  untouched.
- Auto-generating `## Summary`/`## Findings`/`## Risks`/`## Recommendations`/`## Lessons Learned` —
  those require judgment a captured number can't provide; they stay a human/assistant's job.
- A new command verb — this is a flag on the existing `close` (ADR-013: same "flag on an existing
  command" pattern as `--set-assistant` (ADR-031) and `bootstrap --interactive` (Change 0068)).

## Success Criteria

- `aief close --evidence-from <path>` (JUnit XML, valid) fills in `## Verification` with test
  counts and proceeds with the normal readiness report.
- An invalid or missing `<path>`, or a file with no `<testsuite>`, produces a clear error, exit 1,
  and no write.
- Running it twice (e.g. after fixing a failing test) updates the captured numbers without
  duplicating the section or losing any human-written content added since the first capture.
- `aief close` without `--evidence-from` is byte-identical to before this Change.
