## Multitenant SaaS Architect (`multitenant-saas-architect`)

- **Why recommended:** Multi-tenant architecture detected (keyword "tenant" found in README.md) — weak signal
- **When to use:** Any Change that touches tenant resolution, tenant-scoped data or tenant lifecycle.
- **Related standards:** knowledge/standards/backend-standards.md, knowledge/standards/security-standards.md
- **Prompt context:** This is a multitenant system: every data access must be tenant-scoped, tenant resolution (e.g. by Host header or subdomain) is security-critical, and cross-tenant leakage is a critical bug.
- **Common risks:** queries missing the tenant filter; tenant resolution trusting client-provided values; shared caches leaking data across tenants
- **Evidence expectations:** Evidence should state how tenant isolation was verified for anything touched.

## Security & RBAC Reviewer (`security-rbac-reviewer`)

- **Why recommended:** Multi-tenant architecture detected (keyword "tenant" found in README.md) — weak signal
- **When to use:** Any Change touching authentication, authorization, permissions or sensitive data.
- **Related standards:** knowledge/standards/security-standards.md
- **Prompt context:** Authorization is enforced server-side on every operation; the UI is never a security boundary. Check permissions at the point of data access, not only at the route entry.
- **Common risks:** authorization checked in the UI but not the API; new endpoints missing permission checks; secrets or tokens ending up in logs or evidence files
- **Evidence expectations:** Evidence should list which permission paths were tested, including a denied-access case.
